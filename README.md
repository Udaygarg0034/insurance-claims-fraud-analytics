# Insurance Claims & Fraud Analytics | Power BI

An end-to-end Power BI project exploring insurance claim volume, claim amounts, fraud patterns, policy types, customer demographics, and vehicle characteristics. The report is designed as a leadership overview with interactive slicers and supporting detail analysis.

## Project at a glance

| Item | Details |
|---|---|
| Tool | Microsoft Power BI Desktop |
| Source data | `data/insurance_claims_source.csv` |
| Dataset size | 1,000 claims × 39 columns |
| Main target | `fraud_reported` (`Y` = fraud, `N` = non-fraud) |
| Date coverage | 1 January 2015 – 1 March 2015 |
| Main report table | `InsuranceClaims` |

> **Date-scope note:** The assignment brief focuses on January and February, but the source file contains 12 additional records dated 1 March 2015. These rows are retained in the dataset. Use January and February filters for the assignment's monthly-trend visuals; use all 1,000 rows for full-dataset KPIs unless the report page is intentionally filtered.

## Business questions

1. Import and clean the claims dataset.
2. Show total claims, total claim amount, average claim amount, and fraud percentage.
3. Compare claim volume and claim amount for January and February.
4. Compare claim count and claim amount across policy types.
5. Explore fraud vs non-fraud distribution and fraud rates by policy and incident types.
6. Analyze claim behaviour by customer demographics and vehicle characteristics.
7. Enable interactive exploration using slicers and cross-filtering.
8. Present a professional dashboard with evidence-based business insights.

## How to use

1. Download or clone this repository.
2. Open Power BI Desktop.
3. Select **Get data → Text/CSV** and import `data/insurance_claims_source.csv`.
4. Rename the query/table to `InsuranceClaims`.
5. Apply the documented cleaning steps in `docs/data_quality_and_cleaning.md`.
6. Create the DAX measures and calculated columns from `dax/measures_and_columns.dax`.
7. Build the report using `docs/dashboard_guide.md`.
8. Save the finished report in the `powerbi/` folder as an `.pbix` file.

## Data and interpretation notes

- The source contains 1,000 rows and 39 columns; the assignment description mentions 40 attributes, but the supplied CSV has 39 columns.
- `?` is used as a placeholder in three categorical columns. The recommended treatment is to replace it with `Unknown`, not to interpret it as a negative response.
- `authorities_contacted` contains 91 actual blank values.
- One `umbrella_limit` value is negative (-1,000,000). It is flagged for source verification rather than silently changed.
- One policy binding date occurs after its incident date; this is flagged for review.
- Negative `capital-loss` values are retained because they can represent losses.
- No exact duplicate rows were found.
- `total_claim_amount` reconciles to `injury_claim + property_claim + vehicle_claim` for all 1,000 rows.
- Currency is not specified in the supplied file, so this project does not assign a currency symbol.
